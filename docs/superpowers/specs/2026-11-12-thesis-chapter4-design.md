# 论文第四章系统设计写作设计

## 目标

依据现有前后端代码、数据库脚本、接口和推荐流程，完成第四章“系统设计”的可审阅正文。本章说明系统如何由需求转化为可实现的软件结构，并为第五章实现和第六章测试提供对应关系。

## 章节范围

第四章包括：

- 设计目标与原则。
- B/S 架构、前后端分离和分层结构。
- 学生端、管理端、认证权限和公共支撑模块。
- 数据库概念结构与主要数据表。
- HTTP 接口、统一响应和分页数据结构。
- JWT 鉴权、冲稳保计算、数据导入和缓存失效设计。

## 设计约束

- 后端保持单体 Spring Boot 应用和 Controller、Service、Mapper 分层。
- 前端使用 Vue 3，通过 Axios 访问 `/api` 接口。
- JWT 负责登录状态识别，接口上的角色注解负责权限判断。
- MySQL 保存业务数据，Redis 缓存推荐结果，本地运行时允许使用内存缓存。
- 推荐结果最多返回 50 条，只表示历史数据匹配程度，不表示录取概率。
- 数据库设计和接口设计必须与当前代码一致，不提前描述尚未实现的功能。

## 验收标准

- 架构图和功能模块图在正文中有编号、说明和引用。
- 五张核心业务表及其关系能够支撑学生端和管理端主流程。
- 推荐公式、等级阈值、缓存键和失效策略与代码一致。
- 接口分组覆盖主要功能，不复制整个 Swagger 文档。
- 本章不出现虚构的性能指标、用户规模或录取准确率。
