# 管理端录取记录 CSV 批量导入设计

## 背景

管理端已经可以逐条维护院校专业和录取记录。真实数据通常来自表格，逐条录入效率低且容易出错，因此需要为当前院校提供 CSV 批量导入能力。

## 目标

- 管理员在院校数据维护抽屉中上传 CSV。
- 第一版只导入当前院校的录取记录。
- 录取记录的专业必须匹配当前院校已有专业，不自动创建院校或专业。
- 先逐行校验，合法行写入，错误行返回行号、专业信息和错误原因。
- 单行错误不能导致整个文件无法处理或系统异常。
- 导入成功后清除推荐缓存，使学生端查询和推荐及时更新。

## 非目标

- 不导入院校基础信息。
- 不导入或创建专业。
- 不支持 Excel 二进制文件，只支持 UTF-8 CSV。
- 不实现后台异步任务、断点续传或超大文件分片。
- 不自动覆盖数据库中已存在的重复录取记录。

## 方案选择

### 方案一：服务端解析 CSV、逐行校验、部分成功

前端上传 multipart 文件，后端解析并一次性校验，合法行写入，错误行随导入结果返回。

优点是校验规则集中、接口可复用、前端不承担 CSV 兼容逻辑；缺点是后端需要增加文件解析和结果模型。

### 方案二：前端解析后提交 JSON 行

浏览器先把 CSV 转成 JSON，后端只接收结构化记录。

前端实现较快，但不同浏览器和表格软件的 CSV 兼容问题会分裂到前端，错误行定位与后端校验也可能不一致，不采用。

### 方案三：整批事务，全部成功或全部失败

任意一行错误时整批回滚。

数据一致性最强，但管理员修改一个错误后必须反复重传整个文件，不符合本项目对错误行反馈的要求，不采用。

最终采用方案一。

## 文件约定

- 文件格式：UTF-8 编码 CSV，可包含 UTF-8 BOM。
- 文件大小：不超过 2 MB。
- 数据行：表头之外最多 1000 条。
- 首行为表头，列顺序不固定，但列名必须完整且不重复。

必需列：

```text
majorId,majorName,province,year,subjectTrack,batch,minScore,minRank,planCount,source
```

其中 `planCount` 可为空，其余字段必填。`majorId` 和 `majorName` 必须同时填写并相互匹配，防止同名专业造成误导入。

## 接口

```text
POST /api/admin/universities/{universityId}/admission-records/import
Content-Type: multipart/form-data
参数名：file
权限：ADMIN
```

返回 `AdmissionImportResultVO`：

```text
totalRows       数据行总数
successCount    成功写入数量
failedCount     失败数量
errors          错误列表
```

错误项 `AdmissionImportErrorVO`：

```text
rowNumber       CSV 中的实际行号，从数据首行开始计为 2
majorId         当前行填写的专业编号，可为空
majorName       当前行填写的专业名称，可为空
message         中文错误原因
```

全部行都失败时仍返回正常响应，前端展示错误表；文件为空、表头不合法、文件超限等文件级问题返回业务错误。

## 行级校验

- 专业编号必须为数字且在当前院校中存在。
- 专业名称必须与专业编号对应的名称一致。
- 省份、科类、批次和来源不能为空。
- 年份必须在 2000 年至当前年份之间。
- 最低分在 0 至 1000 之间。
- 最低位次大于 0。
- 计划数为空或大于等于 0。
- 同一文件内不能出现重复判定键。
- 不能与数据库中已有录取记录重复。

重复判定键与单条录入一致：

```text
universityId + majorId + province + year + subjectTrack + batch
```

## 后端实现

- 使用 Spring MVC 的 `MultipartFile` 接收文件。
- 使用轻量级 CSV 解析库处理引号、逗号、BOM 和换行。
- 新增独立的导入服务，避免将文件解析和单条 CRUD 混在一个超大方法中。
- 先读取并校验所有数据行，再批量写入合法记录。
- 文件内先记录已出现的重复键，后续相同键直接标记错误。
- 数据库已有记录使用一次查询或按专业和年份范围查询后在内存比较，避免逐行查询。
- 写入成功后清除 `recommendations` 缓存。
- 导入过程使用事务；仅在出现非预期数据库异常时整体回滚，正常行级校验错误不抛异常。

## 前端实现

- 在录取记录页签工具栏增加“批量导入 CSV”按钮。
- 打开导入弹窗，展示文件要求、当前院校名称和模板下载。
- 支持选择或拖入 CSV，显示文件名与大小。
- 导入期间禁用重复提交。
- 导入完成后显示总数、成功数和失败数。
- 错误列表按行号展示专业编号、专业名称和错误原因。
- 成功数量大于 0 时刷新录取记录；推荐缓存由后端在写入成功后清理。
- 全部失败时保留错误列表，允许修正文件后重新选择。

前端提供 CSV 模板下载，模板由已加载的当前院校专业在浏览器端生成，不新增模板接口。模板包含表头、一条专业示例和来源提示“演示数据（非官方）”。

## 测试

后端测试覆盖：

- 正常 CSV 全部导入。
- 合法行成功、错误行失败的部分成功。
- UTF-8 BOM、表头顺序调整和带引号字段。
- 专业不存在、专业名称与编号不匹配。
- 年份、分数、位次和计划数范围错误。
- 文件内重复和数据库重复。
- 空文件、缺列、重复列、超过行数和大小限制。
- 成功导入后缓存失效。

前端测试覆盖：

- 文件大小和扩展名校验。
- 导入结果统计和错误行转换。
- 无专业时禁用导入。

## 验收标准

1. 管理员可以从当前院校的录取记录页签打开 CSV 导入。
2. 合法行写入数据库，错误行返回准确行号和原因。
3. 文件内和数据库中的重复记录不会写入。
4. 专业必须属于当前院校，不能通过 CSV 跨院校写入。
5. 导入后学生端详情和推荐结果能够读取最新数据。
6. 浏览器和接口均有加载、空结果、部分失败和错误状态。
7. 后端测试、前端测试、生产构建和便携环境验证通过。

## 自检结论

本设计保持现有技术栈和院校数据边界，不引入异步任务或自动建专业。文件大小、行数、模板格式和错误反馈均可在本科项目范围内实现。
